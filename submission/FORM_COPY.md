# AI Tower Dense 提交表文案

## 01 作品标题

AI Tower Dense

## 02 作品描述

AI Tower Dense 是一款以“玩家意图可以被编译”为核心的 AI 原生塔防游戏。它借鉴 Vibe Coding 的交互：玩家无需学习内部 API 或编写脚本，只需用自然语言表达“想解决什么问题、想创造什么东西”。AI 会结合当前世界、节点、敌情、材料和历史扩展候选空间，但生成文本或图片并不是终点；只有被游戏内核降为可部署、可触发、可结算、会影响战局的玩法对象，创意才算真正进入游戏。

玩家从世界书与战略地图进入危机，在世界内工坊提出构想并确认试作；可恢复研发任务在后台编译，样品于战斗中途送达。实战会检验效果并暴露缺陷，战后结算再通过受控状态更新，将 NPC 反馈、研发线索、任务和节点变化带回单局世界，形成“创造—试作—战斗—反馈—世界生长”的循环。玩家看到的是世界内评审、材料、风险与战场后果，而不是 prompt、provider 或 schema 错误。

我们把“自由输入”与“有界执行”分开：玩家提供意图，AI 扩大候选空间，但无权执行代码、修改世界事实或自行激活结果。开发者不必预写每一个最终对象，而是定义可组合能力、数值预算、验证方法和发布权限——什么可以被创造、怎样证明它可玩、谁有权让它生效。稳定流程由 AssetGraph DAG 执行，受限 ReAct 只依据校验报告规划与修复；候选须通过 Schema、白名单、确定性模拟、评分、晋升与 Session 激活门，失败则回退到已审查内容。

比赛版本已实现塔、陷阱、支援道具从自然语言提案到战场生效的真实闭环；《长夜灯火》展示战斗、结算与世界状态推进，仙侠、西幻、科幻则是由真实 Provider 在开发期编译并可进入首战的世界实例。AI Tower Dense 的目标不是让 AI 替玩家玩游戏，而是让玩家的想象成为游戏规则的一部分，同时保持平衡、可测试、可审计、可回滚。

## 17 AI 使用说明（300 字以内）

开发侧：CodeBuddy（HY3/GLM-5.2）、OpenCode与Codex用于实现、重构、审查、架构、Worktree并行开发和自动验收，产出Schema、Validator及测试证据。内容侧：DeepSeek/GLM用于世界书与结构化玩法候选，Agnes/OpenAI图像模型与多模态模型用于视觉生成和审查。受限ReAct负责规划修复，AssetGraph DAG负责执行；候选通过白名单、预算、模拟、评分、晋升和Session激活门后才能进入运行时。

## 18 社交媒体发布文案

我们做了一款会“编译玩家想法”的 AI 原生塔防游戏 AI Tower Dense。像 Vibe Coding 一样，玩家说出目标，Compiler 就结合世界书、材料、敌情与规则，把创意变成可部署、可战斗、可结算的新塔、陷阱或支援道具。比赛版还用同一编译体系生成了仙侠、西幻和科幻世界实例。玩家负责想象，Compiler 负责让想象在受控规则内真正运行。
