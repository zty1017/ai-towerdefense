# Compiler 黑客松技术报告草稿

最后更新：2026-07-15

## 1. 项目摘要

`Compiler` 是一个浏览器运行的 AI 驱动塔防游戏原型。项目的核心不是把固定塔防关卡包装成聊天界面，而是把玩家自然语言构想编译成受世界书、玩法规则和运行时预算约束的游戏对象，并在当前战斗中真正执行。

首个演示世界《长夜灯火》只是一份 MVP 世界书模板。系统目标是让不同世界书、玩家状态和战役进度通过同一编译底座长出符合自身语义的防御塔、陷阱、道具、NPC、剧情节拍、任务、事件和地图包。

## 2. 核心命题

玩家输入可以自由，运行时执行必须受控。

系统借鉴传统编译器和 AI 辅助编程的分层思想，将一次生成拆为：

```text
自然语言意图
  -> ContextPackage
  -> 结构化候选
  -> schema 与语义白名单
  -> 确定性模拟与评分
  -> PromotionReport
  -> RuntimePackage
  -> 显式激活门
  -> ActivatedRuntimeBundle
  -> 前端投影与战斗执行
```

LLM 负责理解、推导和提出结构化候选，DAG 负责可复现执行，受限 React 循环只负责审查失败后的局部修复与有限重试。任何模型输出都不能直接写入世界状态或执行任意代码。

## 3. 系统架构

### 3.1 前端运行时

- 原生 ES Modules 与 Canvas 2D，适合无构建浏览器部署。
- 页面控制器负责档案、世界配置、开场、大地图、工坊、战斗和结算。
- `ActivatedRuntimeBundle` 通过 feature gate 投影到玩家界面。
- 战斗对象统一消费 `battle_behavior_abi.v0.1`，当前可执行伤害、范围伤害、连锁、多目标、减速、范围支援和有限生命周期。
- 媒体引用、对象行为、节点身份和地图语义彼此解耦，避免前端继续写死某个世界的塔名或贴图。

### 3.2 后端与状态

- FastAPI 提供匿名 session、世界实例、战役路由、研发任务、战斗结算和运行时激活接口。
- SQLite 保存 session、研究任务、激活回执、战斗结果、世界状态与调度证据。
- 后台 research worker 可恢复未完成任务；前端在进入战斗后继续等待研发样品。
- 玩家侧只显示世界内解释，Provider、模型、trace、schema 和失败细节只进入内部证据。

### 3.3 AssetGraph

真实候选当前执行以下六节点图：

```text
load_candidate
  -> validate_candidate
  -> simulate
  -> score
  -> promotion
  -> summary
```

图节点有明确输入输出、缓存边界和副作用声明。媒体生成、背景移除、画布归一化、视觉审查、候选修复和发布也使用同类节点边界组织。

## 4. 玩家实时编译闭环

玩家在世界内工坊输入构想后，系统会：

1. 结合世界书、当前节点、材料和战斗约束生成一个结构化候选。
2. 使用效果注册表限制能力类型和数值范围。
3. 对真实候选运行确定性战斗模拟，阻断无可玩影响或严重越界候选。
4. 生成 PromotionReport，并校验 RuntimePackage 哈希、session 绑定和媒体来源。
5. 样品在战斗中途送达，通过显式 apply gate 进入当前 session。
6. 前端从 ActivatedRuntimeBundle 动态得到名称、图标、部署方式、费用、冷却、射程与效果。
7. 战斗结算回写使用过的对象和世界变化，为后续内容生成提供事实。

2026-07-15 的真实 Provider 烟测结果：

| 构想 | 文本模型 | 方案耗时 | 总闭环 | 结果 |
| --- | --- | ---: | ---: | --- |
| 密集敌群连锁防御塔 | 方舟 `deepseek-v4-flash` | 11.61 秒 | 12.28 秒 | 生成、模拟、晋升、激活全部通过 |
| 铜镜灯芯跳跃塔 | 方舟 `deepseek-v4-flash` | 约 9 秒 | 9.62 秒 | 首次被 schema 阻断，修复共享契约后用同一候选重新激活通过 |

第二个候选最终 ABI 包含 `damage.amount=40`、`max_targets=3`、`chain_radius_cells=2.4`。前端模拟会寻找两个后续目标并绘制逐段攻击光束，解决了早期“描述有连锁或范围，实战只有单体伤害”的不一致。

## 5. 地图编译

地图不是一张图片。运行时事实由 `MapRuntimePackage` 管理：路线、塔位、出生点、目标、资源、危险区和阻挡区不能从生成图片反推。

视觉 v0.2 将职责拆为：

```text
LogicMapIR
  + VisualMaterialPack
  + MapVisualCompositionPlan
  -> MapVisualRuntimePackage
```

AI 只生成低语义地表材质和独立组件；道路沿结构化样条确定性铺设；塔位、目标和出生点按坐标合成；最后执行色调、接触阴影、视觉审查和人工发布终审。

西幻 `mire_pass` 真实校准曾执行 9 类视觉请求、10 次图像调用、7 次多模态审查、4 次缓存命中和 3 次网络重试。结构对齐通过，但人工终审认为地表过空、道路像描边、塔位重复感强，因此没有替换主演示地图。这证明自动审查通过不等于发布质量通过。

比赛版本的准确口径是：逻辑地图和分层编译已完成；真实 AI 媒体生成、审查、缓存和失败隔离已接通；主演示仍使用人工终审通过的《长夜灯火》地图包。

## 6. 视觉与音频

- 防御塔图片支持 Agnes 生成、白底门禁、多模态审查、受控修复、自动抠图和本地哈希发布；失败时只降级媒体，不让玩法中断。
- 运行时特效由 `visual_recipes` 和前端效果系统叠加，不把攻击光束、爆炸或光环烙死在塔图片中。
- 音频由独立 `AudioDirector` 管理。真实 CC0 东方配乐按开场、大地图、工坊、战斗和结算切换；浏览器媒体加载失败时回退到程序化 Web Audio。
- 首次交互后解锁声音，提供全局静音；部署、陷阱、支援、攻击、击杀、漏失、波次、样品完成和胜负均有事件音效。

## 7. 安全与可治理性

- Provider 密钥只从本地环境读取，不进入前端、数据库或编译包。
- 不保存完整提示词和原始响应体，只保存经过校验的候选、摘要、哈希和必要 provenance。
- RuntimePackage 必须通过 schema、语义、行为 ABI、媒体与 promotion gate。
- 所有数值均裁剪到白名单区间，前端不执行模型生成代码。
- 激活按匿名 session 隔离，支持回执审计和 rollback。
- 媒体失败、Provider 超时和视觉审查失败都有世界内安全降级，不向玩家暴露技术错误。

## 8. 演示链路

推荐录屏顺序：

1. 创建本地匿名档案并选择世界书。
2. 播放开场卡，进入可缩放、可拖动的大地图。
3. 进入危机节点，在现场工坊输入一个此前未预制的塔构想。
4. 展示约 10 秒内生成的唯一方案及世界内风险说明。
5. 确认试作后先进入战斗，使用基础防线拖延。
6. 样品完成并自动激活，工具栏出现模型生成的名称和能力。
7. 部署样品，展示真实范围或连锁行为、攻击范围预览和一次性选择消费。
8. 完成战斗，查看结算、NPC 反馈和大地图进度变化。
9. 最后展示自动导出的 execution trace、PromotionReport 和 RuntimeActivationReceipt。

## 10. 当前边界与后续方向

已真实闭环：玩家研发对象的文本候选、校验、模拟、晋升、激活、前端工具栏和战斗行为。

开发期闭环：地图逻辑与视觉编译、运行时对象图片编译。

受控原型：世界书演化、剧情节拍、随机事件、科技树和 Generation Scheduler 的部分链路。

比赛后优先工作：

1. 将提案文本调用也完全迁入可恢复后台 worker，并加入流式进度事件。
2. 扩展 ABI 的召唤、护盾、修复、持续伤害和资源联动能力。
3. 继续提升道路材质场、塔位组件尺度与地图统一色调，降低人工终审失败率。
4. 让剧情、任务和世界状态变化共享同一事务化编译与激活协议。
5. 用 Catalog 驱动多个真实编译世界，而不是继续扩展固定世界常量。
