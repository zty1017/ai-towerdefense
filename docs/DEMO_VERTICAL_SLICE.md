# MVP 演示垂直切片

Last updated: 2026-06-29

## 1. 目标

本文件定义第一版比赛演示链路。

演示目标：

```text
让评委看到一个正常游戏体验，
同时能证明底层存在 AI 资产编译、世界书约束、运行时战斗和战后世界生长。
```

演示不是完整游戏。

它是一条教学关式 MVP 闭环。

## 2. 录屏节奏

推荐录屏时长：

```text
3-6 分钟
```

结构：

```text
0:00 - 0:20  本地档案入口 / 世界实例配置
0:20 - 0:50  预制开场
0:50 - 1:20  大地图与第一个危机节点
1:20 - 2:00  节点 Briefing 与现场应急研发
2:00 - 3:30  第一场塔防战斗
3:30 - 4:20  战后结算与世界生长
4:20 - 5:00  演示证据导出报告
```

## 3. 演示主线

### 3.1 入口

画面：

```text
游戏启动页 / 本地档案入口
```

玩家动作：

```text
点击开始新档案
```

系统行为：

```text
创建匿名 session
```

旁白重点：

```text
没有复杂账号系统，同一个体验链接会为不同评委创建独立体验会话。
```

### 3.2 世界实例配置

画面：

```text
世界实例配置页
```

玩家动作：

```text
使用默认推荐配置
```

显示内容：

- 世界书模板：`long_night_lanterns`
- 推荐画风。
- AI 创造性。
- 开局身份。

旁白重点：

```text
这里不是角色捏脸，而是创建本次世界实例。
这些选择会影响 NPC 称呼、资源、开场文字、提案约束和素材风格。
```

### 3.3 预制开场

画面：

```text
黑屏白字 + 动画卡
```

内容：

```text
长夜没有结束。
灯塔一座接一座熄灭。
第一个危机点亮起警报。
```

要求：

- 可跳过。
- 不实时生成。
- 使用 reviewed / locked 素材。

### 3.4 大地图

画面：

```text
动态战略态势图
```

必须看到：

- 主城 / 中枢。
- 当前危机战斗热点。
- 补给线。
- 黑暗未知区。
- 移动威胁边缘。
- 悬浮任务 / 警报图标。

玩家动作：

```text
点击第一个危机节点
```

系统行为：

```text
进入节点 Briefing
```

旁白重点：

```text
地图不是固定菜单，而是会随战斗结果、资源和事件变化的战略态势图。
```

### 3.5 节点 Briefing

画面：

```text
节点简报
```

显示内容：

- 当前危机。
- 敌潮特征：高速、低耐久。
- 保护目标：节点核心和一个小型资源 / 设施目标。
- 可用材料。
- 在场 NPC / 设施状态。

玩家动作：

```text
进入现场应急研发
```

### 3.6 现场应急研发

画面：

```text
世界内研发入口
```

注意：

```text
玩家侧不出现 AI、prompt、schema、provider、compiler 等技术词。
```

玩家输入：

```text
我想做一个能拖慢影潮的临时装置。
```

系统行为：

```text
生成 1 个试作方案卡
```

方案卡显示：

- 世界内方案名。
- 一句话描述。
- 预期作用。
- 建议投入 / 可投入材料。
- 已知约束。
- 不确定性 / 研发风险。
- NPC 初步判断。

玩家动作：

```text
确认试作
```

系统行为：

```text
创建研发任务
```

### 3.7 战斗开始

画面：

```text
塔防战斗页
```

布局：

- 左上圆形战略缩略图。
- 顶部状态条。
- 左侧任务事件栏。
- 中央斜视角伪 3D 战场。
- 右侧动态战术面板。
- 底部资产热栏。

初始状态：

```text
样品尚未送达
玩家只能用基础手段拖延
```

显示文案：

```text
样品封装中
正在送达战场
```

### 3.8 样品送达

触发时机：

```text
战斗开始约 30 秒后
```

系统行为：

```text
底部热栏点亮临时减速陷阱样品 x2
```

玩家动作：

```text
在路径转角部署样品
```

表现：

- `ring_pulse`
- `aura_field`
- `sprite_flash`

战斗效果：

```text
高速敌人被明显拖慢
```

旁白重点：

```text
玩家的自然语言构想已经变成了可在战斗中部署的样品。
```

### 3.9 战斗结束

结果建议：

```text
节点守住，但资源设施受损或有少量泄漏。
```

这样既有胜利，也保留后续世界压力。

### 3.10 战后结算

画面：

```text
战后结算 / 世界生长
```

显示内容：

- 战报摘要。
- 节点状态变化。
- 资源 / 设施损伤。
- 样品实战表现。
- 新暴露缺陷。
- NPC 反馈。
- 下一步正式研发线索。

示例结论：

```text
样品对高速敌潮有效，但稳定性偏低。
NPC 记录到光幕干扰方向值得继续研究。
```

玩家动作：

```text
返回大地图
```

### 3.11 返回大地图

画面变化：

- 当前节点状态改变。
- 威胁边缘变化。
- 出现新的研发线索或任务标记。

旁白重点：

```text
战斗结果不是孤立分数，而会反馈到世界状态、NPC 记忆和后续研发方向。
```

## 4. 演示证据

玩家体验结束后，可运行证据导出脚本。

目标输出：

```text
summary.md
evidence.json
index.html
```

证据报告展示：

- session id。
- run id。
- 用户输入摘要。
- worldbook id。
- 方案摘要。
- 编译节点 trace 摘要。
- schema 校验结果。
- mock simulation 摘要。
- locked manifest 资产摘要。
- 战斗结果摘要。

证据报告不得泄漏：

- API key。
- 完整敏感 prompt。
- provider 原始错误栈。
- 未 reviewed / locked 的玩家侧内容。

## 5. 成功标准

演示成功标准：

1. 玩家侧体验像游戏，不像调试工具。
2. 玩家能从自然语言构想到可部署样品。
3. 样品在战斗中产生清晰可见影响。
4. 战后世界状态发生变化。
5. 技术证据可以通过导出报告展示。
6. 整条链路可在演示稳定模式下重复跑通。

## 6. 失败时的降级演示

如果 live provider 或生成服务失败：

```text
使用预生成方案 fixture。
使用预生成 locked manifest。
使用预制图标和 sprite。
证据报告标记为 demo_stable_mode。
```

降级演示仍必须保留：

- 玩家构想输入。
- 方案确认。
- 研发倒计时。
- 战斗中样品送达。
- 战后世界反馈。
